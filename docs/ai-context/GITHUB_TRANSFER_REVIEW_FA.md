# بررسی پیش از انتقال به GitHub

تاریخ بررسی: ۲۰۲۶-۱۰-۳۰. این سند گزارش آماده‌سازی است؛ موفقیت ایجاد Remote یا Push فقط پس از بررسی واقعی آن‌ها ثبت می‌شود.

## محدوده و معماری

- یک برنامهٔ Spring Boot 4.1 با Maven Wrapper و هدف Java 17 در `com.factory.productmanager`؛ لایه‌های Controller، DTO، Service، Repository، Entity و Security در یک Backend هستند.
- Frontend در `src/main/resources/static` شامل HTML/CSS، JavaScript کلاسیک، فونت و تصاویر است و از همان برنامه سرو می‌شود. پروژهٔ npm یا Repository مستقل Frontend وجود ندارد.
- در شروع این مرحله، نه `.git`، نه Git history و Remote و نه Repository تو‌در‌تو در پوشه‌های سورس وجود داشت. مخزن محلی جدید با Branch نام `main` ایجاد شد. بنابراین تاریخچهٔ قبلیِ محلی برای پاک‌سازی وجود ندارد؛ دربارهٔ کپی‌های احتمالی در محل‌های دیگر ادعایی نمی‌شود.
- هیچ تغییری در منطق تجاری، قرارداد API، Entity، Schema، تنظیمات اجرایی موجود یا رابط کاربری در این مرحله انجام نشد. فایل‌های سورس/Build پیش از کار SHA-256 شدند و برای کنترل عدم تغییر نگه داشته شدند.

## محتوای قابل انتشار

سورس Backend و Frontend، تمام تست‌ها و ابزارهای تست، `pom.xml`، دو Maven Wrapper، تنظیمات wrapper، migrationها، fixture ساختاری بدون رکورد، Workflowهای GitHub، اسکریپت‌های توسعه، مستندات، README، AGENTS.md، `.gitignore`، `.gitattributes` و `.env.example` در مجموعهٔ انتشار قرار دارند.

هیچ منبع خارجی به‌عنوان submodule وجود ندارد. Maven وابستگی‌های کتابخانه‌ای را دریافت می‌کند؛ فونت‌ها و تصاویر موردنیاز رابط داخل سورس هستند. فایل‌های IDE برای Build موردنیاز نیستند.

## بررسی امنیتی و استثناها

- تنظیمات MySQL و JWT در فایل عمومی از متغیرهای محیطی خوانده می‌شوند. اطلاعات واقعی اتصال و کلیدهای محیط اجرایی جزو مجموعهٔ انتشار نیستند.
- بررسی الگوهای شناخته‌شدهٔ Token/API key، کلید خصوصی، credential داخل URL و تطبیق مقادیر محرمانهٔ شناخته‌شده انجام شد. این بررسی ضمانت مطلق نبود تمام انواع راز نیست؛ فقط حدود بررسی انجام‌شده را نشان می‌دهد. مقدار هیچ رمز یا Token در گزارش درج نمی‌شود.
- رمزها و کلیدهای ثابت باقی‌مانده در فایل‌های تست، دادهٔ ساختگی تست H2/واحد هستند؛ تنظیمات MySQL تست توسط سرور مستقل تحت مالکیت تست جایگزین می‌شوند و به دیتابیس اصلی متصل نمی‌شوند. ابزارهای تاریخی `src/test/audit` خودکار اجرا نمی‌شوند و برای دیتابیس اصلی مجوز اجرا ندارند.
- `target`، `build`، `node_modules`، `uploads`، `tmp`، IDE، فایل‌های موقت/Log، فایل‌های properties خصوصی، `.env` واقعی، کلیدها، credential store و پشتیبان‌ها نادیده گرفته می‌شوند. خروجی ماشینی ممیزی نیز محلی نگه داشته می‌شود؛ گزارش‌های Markdown بررسی‌شده حفظ می‌شوند.
- همهٔ SQLها به‌طور پیش‌فرض نادیده گرفته می‌شوند، با دو استثنای روشن: migrationهای سورس و `src/test/resources/db/mysql/schema-synthetic.sql`. fixture فقط ساختار جدول‌ها را دارد؛ فاقد رکورد، امضا، فایل نقشه، رمز و migration-history واقعی است.
- پشتیبان واقعی و تنظیمات خصوصی قبلی در پوشه‌ای خارج از Repository باقی می‌مانند. این مرحله به دیتابیس اصلی متصل نمی‌شود و هیچ عملیات داده یا Schema انجام نمی‌دهد.
- فایل‌ها حذف نشده‌اند؛ نادیده‌گرفتن در Git، پاک‌کردن فایل از لپ‌تاپ نیست.

## تغییرات مجاز این مرحله

قواعد انتشار در `.gitignore`، نمونهٔ خالی `.env.example`، README، تکمیل AGENTS.md و راهنماهای GitHub/Cloud اضافه یا اصلاح شدند. اشارهٔ Markdown به JSON تولیدشدهٔ محلی از حالت لینک قابل انتشار خارج شد. کد برنامه و منابع آن دست‌نخورده‌اند.

## وضعیت و نتیجهٔ بررسی

- فهرست Stage‌شده: **۵۳۶ فایل، حدود ۴٫۹ مگابایت**؛ شامل تمام **۵۱۲ فایل سورس/Build** ثبت‌شده در کنترل اولیه، با صفر فایل مفقود و صفر تغییر در SHA-256 نسخهٔ کاری آن‌ها. تفاوت حجم با فایل‌های کاری از نرمال‌سازی متنی اولیهٔ Git و فایل‌های مستندات است.
- بررسی blobهای واقعی Stage‌شده: صفر مسیر ممنوع، صفر تطبیق الگوهای credential بررسی‌شده، و صفر لینک محلی Markdown شکسته. فایل واقعی `.env`، خروجی Build، آپلود یا پشتیبان در Index نیست.
- فقط از Index یک پوشهٔ پاک استخراج شد و `bash mvnw -B -ntp verify` در آن **موفق** بود: ۲۹۳ تست شناسایی‌شده، **۲۳۶ اجراشده با صفر خطا** و ۵۷ مورد اختیاری غیرفعال. Build و بسته‌بندی JAR نیز موفق بود. تست‌ها H2 و فضای آپلود مستقل همان پوشه را استفاده کردند؛ هیچ اتصال MySQL اصلی انجام نشد. این اجرا روی JDK 25 با هدف کامپایل 17 بود؛ نتیجهٔ GitHub-hosted JDK 17 باید بعد از Push بررسی شود.
- مجوز اجرایی لینوکس برای `mvnw` و دو اسکریپت shell توسعه در Index ثبت شد. شش هشدار whitespace در سورس موجود دیده شد؛ به‌دلیل ممنوعیت تغییر سورس در این مرحله، خطوط کد/asset دست‌کاری نشدند. این هشدارها مانع Build و تست نبودند.
- Git نسخهٔ 2.55 و نسخهٔ قابل‌حمل رسمی GitHub CLI نسخهٔ 2.103.3 آماده‌اند؛ SHA-256 آرشیو CLI با manifest رسمی تطبیق داده شد. ابزار و فایل‌های موقت آن زیر `target/` هستند و منتشر نمی‌شوند.
- ورود CLI با حساب `aliidolati` تأیید شد. نبود مخزنی با نام درخواستی قبل از ایجاد بررسی شد؛ سپس [Repository خصوصی casting-production-management](https://github.com/aliidolati/casting-production-management) ساخته شد و پاسخ API، `private=true` و مخزن خالی را تأیید کرد.
- `origin` به `https://github.com/aliidolati/casting-production-management.git` تنظیم شد؛ Branch محلی `main` است. هویت Commit فقط در تنظیمات همین مخزن، با شناسهٔ عمومی حساب و ایمیل GitHub noreply ثبت شد؛ ایمیل شخصی وارد Commit نمی‌شود.
- این گزارش همراه نخستین Commit محلی ثبت می‌شود. شناسهٔ دقیق Commit در گزارش نهایی به کاربر ارائه می‌شود. **هیچ Push انجام نشده است**؛ ارسال همین Commit به `origin/main` به تأیید جداگانهٔ کاربر نیاز دارد. بررسی SHA و محتوای Remote و اجرای GitHub Actions پس از آن انجام می‌شود.

تا قبل از تأیید صریح کاربر، هیچ Push انجام نمی‌شود. اگر نام مخزن از قبل وجود داشته باشد، ادامهٔ کار به هماهنگی نیاز دارد و حذف، بازنویسی یا Force Push مجاز نیست.

انتشار باید به Repository با نام `casting-production-management` و وضعیت **PRIVATE** انجام شود. پس از Push لازم است `origin`، Branch اصلی، SHA راه‌دور و محتوای tree بررسی شوند؛ وضعیت تست‌های GitHub Actions جداگانه گزارش شود.
